PFE — Chatbot Intelligent pour Marketplace ASMAD

Université / Encadrant / Étudiant : à compléter

  • Problème : aider l'utilisateur à trouver rapidement le bon produit
  • Solution : chatbot hybride (règles métier + RAG + génération IA)
  • Impact : meilleure conversion, meilleure expérience client

1) Contexte et Problématique

  • Une marketplace contient beaucoup de produits : la recherche classique n'est pas toujours suffisante.
  • L'utilisateur exprime souvent son besoin en langage naturel : "je veux un article pour...".
  • Objectif : transformer une demande textuelle en recommandations concrètes.
  • Contrainte : ne proposer que des produits disponibles et réellement existants en base.

Message clé : le chatbot est un assistant d'achat, pas un simple gadget.

2) Objectifs du Chatbot

  • Comprendre la demande utilisateur en français.
  • Récupérer des produits pertinents (titre, description, catégorie).
  • Répondre avec texte + recommandations structurées (id, nom, prix, image).
  • Garder un mode dégradé sans clé OpenAI.
  • Intégrer des réponses prédictives selon le rôle (admin / vendeur).

3) Stack Technique

  • Frontend : Vue 3, Vue Router, Axios
  • UI : widget de chat intégré dans l'application
  • Auth : JWT côté client
  • Backend : NestJS 11, TypeORM, MySQL
  • IA : OpenAI (chat + embeddings)
  • Sécurité : JwtAuthGuard, contrôle des rôles

Important : gestion des images via API interne (upload + base), pas Cloudinary.

4) Architecture du Chatbot

  • Endpoint principal : POST /chat (protégé par JWT).
  • Endpoint d'indexation : POST /chat/reindex (admin uniquement).
  • Service central : ChatService.
  • Service vectoriel : EmbeddingService.
  • Réponse type : { reply, recommended[] }.

5) Pipeline de Traitement

  • 1. Validation du message utilisateur (ChatRequestDto).
  • 2. Détection d'intention spéciale (prévision pour admin/vendeur).
  • 3. Chargement du catalogue disponible (status DISPONIBLE + stock > 0).
  • 4. Filtrage mots-clés + ranking sémantique (cosine similarity).
  • 5. Génération de réponse contrôlée (prompt système anti-hallucination).

6) Stratégie RAG Implémentée

  • Le système n'envoie pas tout le catalogue : il envoie un contexte top-K.
  • Contexte = intersection "match lexical" + "similarité vectorielle".
  • Embeddings stockés en base (embeddingJson) et réindexables.
  • Le modèle reçoit des règles strictes : ne recommander que les produits du contexte.
  • Résultat : réponse plus précise, moins d'hallucinations.

7) Mode Dégradé (Sans OpenAI)

  • Si OPENAI_API_KEY est absente, le chatbot reste fonctionnel.
  • Mode fallback : filtrage par mots-clés uniquement, sans génération LLM.
  • Réponse explicite pour guider l'utilisateur vers de meilleurs mots-clés.
  • Avantage : robustesse de service même en cas de panne externe.

8) Fonctionnalité Avancée : Prévisions

  • Le chatbot détecte des intentions de type "prévision" dans le message.
  • Admin : projection du CA/profit plateforme sur 5 mois.
  • Vendeur : projection des unités vendues sur 5 mois.
  • Méthode actuelle : régression linéaire sur historique mensuel.
  • Valeur : assistant décisionnel, pas seulement assistant commercial.

9) Sécurité et Gouvernance

  • Accès au chat protégé par JWT (JwtAuthGuard).
  • Réindexation réservée aux administrateurs.
  • Validation DTO pour limiter les payloads invalides.
  • Gestion d'erreurs OpenAI : indisponibilité proprement remontée.
  • Recommandation PFE : rate limiting + logs structurés + monitoring.

10) Démonstration (Script oral 2-3 min)

  • Cas 1 : "Je cherche un téléphone à petit budget" → produits proposés.
  • Cas 2 : "Prévision de ventes sur 5 mois" avec compte vendeur.
  • Cas 3 : arrêt de la clé OpenAI → bascule automatique en mode fallback.
  • Cas 4 : reindex admin après import de nouveaux produits.

Astuce soutenance : montrer au jury une réponse correcte + une réponse refusée (produit absent), pour prouver le contrôle des hallucinations.

11) Résultats et Bénéfices

+UX

  • Recherche plus naturelle
  • Moins de friction dans le parcours
  • Réponses contextualisées

+Métier

  • Mise en avant des produits pertinents
  • Vision prévisionnelle simple
  • Architecture extensible

12) Limites Actuelles

  • Évaluation qualité à formaliser avec un jeu de tests conversationnels.
  • Métriques chatbot (taux de clic, conversion assistée) à instrumenter davantage.
  • Régression linéaire utile mais limitée face aux saisonnalités complexes.
  • Stockage image en base à revisiter pour très grande échelle.

13) Feuille de Route

  • Passer à un vrai pipeline d'évaluation (précision recommandation, satisfaction).
  • Ajout de mémoire conversationnelle contrôlée et profils d'intention.
  • A/B testing entre différentes stratégies de récupération.
  • Observabilité complète (traces, coûts token, latence P95).
  • Durcissement production : cache, files d'attente, quotas et alerting.
